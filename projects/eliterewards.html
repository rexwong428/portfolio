What it is

A live production rewards platform for traders. Members earn points against trading activity and redeem them against real inventory, which means the points ledger has to balance, the member records have to be right, and the trading data flowing in from a broker API has to reconcile against what the platform believes happened. My work is the data layer underneath all of that, plus the reporting the business reads off it.

Keeping the records correct

Day to day, this is data accuracy, completeness and consistency across member accounts, contact records, statuses and transaction data. The core processes are cleansing, deduplication, reconciliation and enrichment, run across member, trading and transaction records rather than against a single table, because a member is only correct if all three agree.

Reporting built on top

Recurring reports and dashboards covering monthly statements, P&L, activity metrics and account reconciliation. These are the reports the business actually operates on, so they are built to be re-run rather than rebuilt, and the reconciliation view exists so that a number in a statement can always be traced back to the records behind it.

The migration

Delivered a full production data migration end to end: schema migration, record consolidation, cross system reconciliation, and post cutover catch up sweeps. Completed with zero data loss. The catch up sweeps are the part that matters. A migration is not finished when the rows land, it is finished when the two systems agree on every row that moved during the cutover window.

Broker integration

Integrated the Tradovate API so trading accounts connect automatically, trade data synchronises and reconciles on an ongoing basis, historical backfills are processed, and accounts that need reconnecting are identified rather than quietly going stale. Broker fill data does not stay available indefinitely, so a sync that silently stops is a data loss problem, not an inconvenience.

Automating fulfilment

Automated the reward fulfilment lifecycle from end to end: validating balances and inventory before anything is committed, allocating redemption codes atomically so the same code cannot be issued twice, processing scheduled requests, sending redemption emails, and supporting the administrative workflows behind restocking, held redemptions, approvals and points adjustments. Outbound communications to segmented recipient lists run on managed templates with versioning, BCC handling, delivery tracking and re-send rules.

Why this one is here

The other projects on this site are analyses of datasets that were handed to me. This one is a system that other people depend on being right, where the data is generated by real activity, arrives incomplete, and has to be reconciled before any reporting on top of it means anything. It is the closest thing here to the work itself.
